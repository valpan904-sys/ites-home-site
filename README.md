# Сайт ООО «ИТЭС-Хоум»

Многостраничный сайт строительно-монтажной компании (Самара): `home.ltd-ites.com`.
Каждая страница — готовый HTML (текст, заголовки и мета-теги видны поисковикам сразу),
JavaScript только «оживляет» страницу: меню, галереи фотографий, форма заявки.

## Быстрый старт

```bash
npm install       # один раз
npm run dev       # http://localhost:3000 — живая перезагрузка при правках
npm run build     # сборка в dist/public: страницы, sitemap.xml, 404.html
npm run preview   # посмотреть то, что собралось
```

Проверять собранную статику удобнее простым сервером:

```bash
cd dist/public && python -m http.server 8899   # http://127.0.0.1:8899/
```

## Где что лежит

```
src/content/       весь текст сайта — правится без вёрстки
  site.ts            название, телефон, адрес, соцсети, меню
  projects.ts        объекты: клиент, город, состав работ, ссылки на галерею и кейс
  services.ts        услуги и примеры работ
  documents.ts       документы (СРО, сертификат, политика, презентации, кейсы)
  banks.ts           банки-партнёры
  galleries.json     список фотографий в галереях
src/pages/         страницы: главная, объекты, услуги, документы, контакты, 404
src/components/    шапка, подвал, галерея с просмотром, хлебные крошки
src/lib/routes.ts  список адресов + заголовки/описания/разметка для поисковиков
public/            копируется в сборку как есть: PDF, фото объектов, шрифты, .htaccess
assets/            исходные картинки (обложки объектов, услуги, логотипы)
scripts/           сборка: сборка клиента + серверный рендер страниц
tools/             вспомогательные скрипты (медиа, шрифты)
```

## Как добавить объект

1. Фотографии загрузить в `public/media/projects/<адрес>/` (большие `NN.webp` и превью
   `NN-t.webp`), PDF-кейс — в `public/documents/`.
2. Добавить запись в `src/content/projects.ts`: `slug`, клиент, название, город,
   состав работ, ссылка на галерею и кейс.
3. Добавить фотографии в `src/content/galleries.json` по этому `slug`.
4. `npm run build` — страница объекта, ссылка в списке объектов, пункт в sitemap.xml
   и мета-теги собираются автоматически.

То же самое для услуг — правка в `src/content/services.ts`.

## Правила проекта

- **Текст и данные живут только в `src/content/`.** В вёрстке страниц текста быть не должно —
  иначе его нельзя будет поправить, не залезая в разметку.
- **Адреса страниц — со слэшем на конце** (`/projects/`), так они и в `sitemap.xml`,
  и в редиректе на сервере.
- **Никаких внешних доменов.** Шрифт, фотографии, документы — только со своего сервера.
  Ссылки на VK, Telegram, 2ГИС и Яндекс.Карты — исключение, это профили компании.
- **Заголовок и описание для каждой страницы** задаются в `src/lib/routes.ts`, страница
  без них собраться не сможет.
- `dist/` пересоздаётся при каждой сборке — правки в него вносить бессмысленно.

## Публикация

**Демо-версия для коллег: <https://valpan904-sys.github.io/ites-home-site/>** — ссылка открывается
в браузере у любого человека, ничего устанавливать не нужно. Поисковикам демо закрыто
(`noindex`), форма заявки на демо не отправляет письма — там нет PHP.

Обновить демо-версию (одна команда):

```bash
bash tools/deploy-demo.sh     # сборка + публикация в ветку gh-pages
```

Скрипт собирает сайт с префиксом `/ites-home-site/`, помечает страницы `noindex, nofollow`
и публикует результат в ветку `gh-pages`, откуда GitHub Pages его раздаёт.

**Боевой сайт** `home.ltd-ites.com` живёт на хостинге reg.ru: выкладывается вручную
(папка `dist/public` целиком), там же работает форма заявки (`public/send_form.php`).

Порядок работы: правки → `npm run dev` (посмотреть локально) → `bash tools/deploy-demo.sh`
(показать коллегам) → после утверждения коммит и push в `main`.

## Форма заявки

`public/send_form.php` отправляет письмо через SMTP Яндекс 360. Пароль приложения
хранится **вне** сайта, в файле `~/secrets/mail_credentials.php` на хостинге, в репозитории
его нет. В демо-версии форма не работает — там нет PHP.
