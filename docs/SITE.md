# Сайт ИТЭС-Хоум — как всё устроено

Проект собирается в статический сайт: каждая страница — готовый HTML с текстом,
заголовками и мета-тегами; JavaScript добавляет поведение (меню, галереи, форма).

## Команды

```bash
npm install        # один раз
npm run dev        # разработка: http://localhost:3000
npm run build      # сборка в dist/public: страницы + sitemap.xml + 404.html
npm run preview    # посмотреть собранное
npm run typecheck  # проверка типов
```

Проверить собранную статику «как на хостинге» надёжнее всего обычным сервером:

```bash
cd dist/public && python -m http.server 8899    # http://127.0.0.1:8899/
```

## Структура

```
src/content/        весь текст и данные сайта
  site.ts             название, телефон, адрес, соцсети, пункты меню
  projects.ts         объекты: клиент, город, состав работ, галерея, кейс
  services.ts         услуги, примеры работ
  documents.ts        документы: СРО, сертификат, политика, презентации, кейсы
  banks.ts            банки-партнёры
  galleries.json      фотографии галерей (создаётся tools/build-media.py)
  documents-map.json  соответствие PDF и видео (создаётся им же)
src/lib/routes.ts   список страниц + title/description/JSON-LD для каждой
src/lib/head.ts     генерация <head> и обновление мета-тегов при переходах
src/components/     шапка, подвал, галерея с просмотром, хлебные крошки
src/pages/          страницы: главная, объекты, услуги, документы, контакты, 404
src/entry-server.tsx  вход для серверного рендера (используется пре-рендером)
public/             уходит в сборку как есть: PDF, фото объектов, шрифты, .htaccess, send_form.php
assets/             исходные изображения интерфейса (обложки объектов, услуги, логотипы)
scripts/prerender.mjs  сборка: клиент → серверный рендер → страницы, sitemap, 404
tools/              вспомогательные скрипты: медиа объектов, шрифт
```

## Как добавить объект (страницу объекта)

1. Фотографии: `public/media/projects/<slug>/01.webp`, `01-t.webp` (большая и превью).
   Чтобы добавлять пачкой — положить архив с фото в папку исходников и выполнить
   `bash tools/build-media.sh` (нужен Python с Pillow, для видео — ffmpeg).
2. PDF-кейс: `public/documents/case-<slug>.pdf`.
3. Запись в `src/content/projects.ts`: `slug`, `client`, `title`, `location`, `items`,
   `galleryFrom`, `doc`, `services`.
4. Фотографии в `src/content/galleries.json` по этому же `slug`.
5. `npm run build` — страница объекта, ссылка в списке, пункт в sitemap.xml и мета-теги
   появятся автоматически.

Так же добавляется услуга — правкой `src/content/services.ts`.

## Что происходит при сборке

1. Vite собирает клиентскую часть → `dist/public`.
2. Vite собирает `src/entry-server.tsx` → `dist/ssr` (рендер на Node).
3. Для каждого маршрута из `src/lib/routes.ts` берётся `index.html`, в него подставляются
   отрисованная страница и её `<head>` (метки `<!--HEAD-START-->` и `<!--APP-HTML-->`),
   результат пишется в `dist/public/<адрес>/index.html`.
4. Дополнительно создаются `404.html` и `sitemap.xml`.

Переменные окружения сборки:

| Переменная | Значение | Зачем |
|---|---|---|
| `BASE_PATH` | `/` | путь, по которому публикуется сайт (для демо на GitHub Pages — `/<репозиторий>/`) |
| `PREVIEW` | — | `1` — демо-сборка: страницы получают `noindex, nofollow` |
| `PORT` | `3000` | порт dev-сервера |

## Правила, которые важно не нарушать

- **Текст — только в `src/content/`.** В вёрстке страниц текста быть не должно.
- **Адреса страниц со слэшем на конце** (`/projects/`) — так они и в sitemap, и в `.htaccess`.
- **Внешних загрузок нет.** Шрифт, фотографии, документы — со своего домена. Ссылки на VK,
  Telegram, 2ГИС и Яндекс.Карты — это профили компании, они допустимы.
- **title и description** задаются в `src/lib/routes.ts`; страница без них не соберётся.
- `dist/` пересоздаётся при каждой сборке — правки в нём бессмысленны.
- Пароль от SMTP живёт вне сайта: `~/secrets/mail_credentials.php` на хостинге,
  в репозитории его нет и быть не должно.

## Демо-версия и боевой сайт

- **Демо (для обсуждений)** — `.github/workflows/deploy.yml`: при каждом push сайт
  собирается (видно, что правки не сломали сборку), а при включённой переменной
  репозитория `ENABLE_PAGES=1` обновляется и демо-версия. Форма заявки там не работает:
  на статическом хостинге нет PHP.
- **Боевой сайт** `home.ltd-ites.com` — хостинг reg.ru: выкладывается вручную
  (папка `dist/public` целиком). Там же работает форма заявки (`public/send_form.php`).

## Что нужно для внешних сервисов

- **Яндекс.Метрика**: номер счётчика в `scripts/metrika-id.txt`, затем пересборка.
  Разрешения в CSP (`.htaccess`) уже прописаны.
- **Google Search Console**: файл подтверждения в `public/`, пересборка.
- **DKIM/DMARC** — настройки DNS домена, к сайту отношения не имеют.
